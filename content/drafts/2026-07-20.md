今天整天在做一件很無聊、但做下去發現不無聊的事:把測試裡一堆 `skip` 掉的案例翻出來,一個一個問它「你到底是真的測不了,還是當初有人放棄得太早」。

前提先講清楚,不然後面看不懂:這是一套跨平台的 E2E,同一支 spec 同時跑兩個行動平台,靠啟動時注入的 mock 回應去湊出各種後端情境(某端點回成功、回鎖定、回額度不足…)。很多測案的頂上都掛著一行 `this.skip('...')`,理由五花八門。而 `skip` 的理由有個很陰的性質——它不會過期,也不會有人再回去驗一次。寫下的那一刻是什麼狀態,它就一直是什麼狀態,慢慢從「事實」爛成「傳說」。

## 「這頁根本不驗密碼」——結果只是 mock 指錯地方

第一個踩到的就是這種。有個測案要驗「密碼輸錯到鎖定、跳出鎖定彈窗」,頂上寫著大意是「這個平台在這頁不會驗密碼,所以造不出鎖定彈窗」,skip。

我照理由的反面去試:塞一個「應該回鎖定」的 mock 進去,重跑。結果畫面直接跳去了下一關的 OTP,鎖定彈窗連影子都沒有。

第一個念頭是:那就對了嘛,skip 理由成立,收工。

但我停了一下,因為「跳去 OTP」這件事有點可疑——如果它真的完全不驗,應該是原地不動或報個泛用錯誤,而不是**當成驗過了**往下走。於是回頭查我 mock 到底注在哪個端點。

注錯了。我塞的是**另一個平台**在這步用的端點;這個平台在這步讀的是別的端點。我等於在對著一扇沒接線的開關猛按,難怪它把「沒收到失敗」當成「通過」。把 mock 改注到對的端點,鎖定彈窗跳出來了,測案綠燈。

所以那行 skip 理由從頭到尾是假的——不是「這頁不驗密碼」,是**當初給理由的人 mock 指錯了地方,然後把工具的失敗寫成了產品的行為**。沒人再查證,它就這樣掛在那裡當事實用。

## 反過來的一個:跑完才甘願把 skip 留著

同一天也有反例,而且我一開始很得意。

有個測案要驗「確認階段額度不足」的情境。整條流程有兩個關卡會擋額度:前面的估算階段,後面的確認階段。我讀 mock 回應時注意到——這兩個關卡的額度**來自不同端點**,而且估算階段拿到的上限,看起來比確認階段實際核准的額度**大**。

那不就成了嗎?輸入一個卡在兩者中間的金額:大於確認額度、但小於估算上限。它會順順過掉估算,然後在確認頁撞上不足。不用新增 mock、不用重 build,一個金額就把隔離情境湊出來了。漂亮。

跑下去。卡在第一頁。

輸入框直接就不讓我打到那個中間值——第一頁的上限**已經是那個比較小的數字**了。也就是說兩個關卡實際上共用同一條額度線,我想像中「估算放行、確認擋下」的中間地帶根本不存在。原本那行 skip 理由(這個情境沒辦法在這套工具下隔離出來)是對的。

差別在於:早上那個是「理由假的,翻案」;這個是「理由真的,留著」。但兩個都得先真的把它跑一遍才知道是哪一種。skip 的理由值不值得信,不看它寫得多有道理,看有沒有人最近真的去撞過那面牆。

## 一個 helper 在導航成功的時候,丟了例外

最後這個純技術,但我卡了一陣子才看懂,值得記。

有個 page object 的 helper,大意是「送出金額、確認已經前進到下一頁」。它內部長這樣(示意,通用命名):

```js
// helper:送出金額後,靠「下一頁才有的元素」來確認導航成功
async submitAndProceed() {
  await this.amountField.setValue(amount)
  await this.nextButton.click()
  await this.bankField.waitForDisplayed({ timeout: 15000 }) // ← 只有預設分支才有這一欄
}
```

在預設路徑上完全正常。但有個測案跑的是另一種設定:預設的收款方式被關掉,畫面會自動落到另一個分頁(第三方錢包那頁)。那一頁**沒有** `bankField` 這一欄。於是 `waitForDisplayed` 等到逾時、丟例外,測案紅掉。

我一開始去查導航是不是壞了。dump 出當下的畫面才發現:導航根本沒問題,頁面**確確實實**已經切到錢包那頁了,錢包欄位、餘額什麼都在。壞的不是流程,是這個 helper 對「成功」的定義——它把「有沒有到下一頁」綁死在只有預設分支才存在的那一欄上。走另一條合法分支,它就把成功誤判成失敗。

修法不是去動導航,是去鬆綁 helper 的誤報:

```js
await page.submitAndProceed().catch(() => {}) // 導航其實成功了,只是 helper 在等一個這條分支沒有的元素
await expect(page.walletField).toBeDisplayed()  // 改成斷言「這條分支自己該有」的元素
```

紅燈指著 helper,不是指著 app。要是我當時信了紅燈、跑去「修」那條根本沒壞的導航,才是真的浪費一個下午。
