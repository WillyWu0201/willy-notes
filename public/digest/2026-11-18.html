Running the full server-side Datasette Python app in the browser with service workers and Pyodide

Datasette Lite 改用 service worker 重寫後，幾乎能在瀏覽器裡完整重現伺服器端的 Python 應用；作者主張這種 WebAssembly 預覽環境可成為 Python 生態系做展示與重現 bug 的通用作法。

重點

  • 新版用 service worker 攔截頁面與靜態資源請求，交給背後的 web worker 執行 Pyodide 裡的 Datasette，解決舊版用 innerHTML 注入導致 JavaScript 無法執行的問題。
  • 每個分頁用隨機 session 前綴區分，讓不同網址設定（外掛、資料庫、版本）各自跑獨立實例，不會共用同一個 service worker 狀態。
  • 整個狀態寫在網址裡：可指定 Datasette 版本或 Git 分支、外掛、資料庫，甚至 SQLite 版本，作者已直接用兩條連結在 issue 裡對照 bug 修正前後。
  • 這個架構五月先由 Claude 做出研究原型，作者到十一月才熟悉到敢上線；SQLite 多版本比對工具與說明圖也是請 Claude 產生的。
  • 作者認為多數 Python 應用都能比照辦理，C 或 Rust 擴充套件現在也能交給 coding agent 編成 WebAssembly，主要缺口是 PostgreSQL、MySQL 這類資料庫。

反思問題

  • 你的專案回報 bug 時，能不能附一個別人點了就能重現的連結？
  • AI 幫你做出能動的原型之後，你需要理解到什麼程度才敢把它上線？
  • 有哪些「要開一台伺服器才能展示」的情境，其實可以搬到瀏覽器裡跑？

延伸閱讀

  • Datasette Lite：本文主角，在瀏覽器中以 Pyodide 執行的 Datasette。
  • URL-addressable Pyodide Python environments：作者先前談如何把整個 Python 環境設定寫進網址的文章。
  • pyodide-asgi-browser 研究原型：新版架構的前身，由 AI 產生的研究 spike。
  • datasette/pysqlite3-wasm-wheels：收錄 163 個 SQLite 版本的 WebAssembly wheel，支援指定 SQLite 版本。
  • Service Worker API：新版用來在瀏覽器端攔截並回應 HTTP 請求的機制。
