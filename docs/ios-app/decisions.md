# 日知 iOS App 決策紀錄

這份檔案記錄開發「日知」iOS App 過程中，我自己判斷、規格沒有寫死的決定。每一筆寫下當時遇到的問題、考慮過的做法、最後選了哪個，以及選錯時怎麼改回來。

## 2026-11-18 · 網站 JSON · 每天的 JSON 多一個 generatedAt 欄位

- 遇到什麼問題：規格只在 `index.json` 放 `generatedAt`，但 App 要顯示「M/d HH:mm 更新的內容」，離線時看的是某一天的內容，不一定是最新那天。
- 考慮過的做法：(1) 只用 `index.generatedAt`；(2) 每天的 JSON 各自加 `generatedAt`；(3) 讓 App 自己記下下載時間。
- 選了哪個、為什麼：選 (2)。那一天的更新時間跟那一天的內容綁在一起，不受下載時間影響。規格允許只加欄位，`schemaVersion` 不用動，舊版 App 會直接忽略。
- 選錯的代價：每天的檔案多一行，幾乎沒有成本。
- 怎麼改回來：拿掉 `digest-api.mjs` 裡的欄位並重新建置。App 端把它當選填欄位，拿掉也不會壞。

## 2026-11-18 · 網站 JSON · index.generatedAt 用最新一天的時間

- 遇到什麼問題：`buildAll()` 每天 09:00 都會跑，如果 `index.generatedAt` 用建置時間，內容沒變也會多一個 commit，等於每天都有無意義的變動。
- 考慮過的做法：(1) 用建置當下時間；(2) 用最新一天的 `generatedAt`；(3) 不放這個欄位。
- 選了哪個、為什麼：選 (2)。內容沒變，輸出的檔案就逐位元組相同，不會產生新 commit。規格有這個欄位，所以不能拿掉。
- 選錯的代價：`index.generatedAt` 代表「最新內容的產生時間」，不是「網站最後一次建置的時間」。App 只拿它當參考，影響很小。
- 怎麼改回來：改成建置時間，並接受每天多一個 commit。

## 2026-11-18 · 網站 JSON · 同一天網址相同的文章去重

- 遇到什麼問題：`id` 是網址的雜湊，同一天若有兩篇網址相同的文章，`id` 會重複，App 的收藏、已讀和列表辨識都會出問題。
- 考慮過的做法：(1) 不處理，相信資料不會重複；(2) 只輸出第一篇；(3) 在 id 後面加序號。
- 選了哪個、為什麼：選 (2)。`id` 要維持「同一篇文章永遠同一個 id」才能讓收藏跨天有效，加序號會破壞這點。順序依網頁的分組順序，所以留下的是網頁上最先出現的那篇。
- 選錯的代價：如果兩篇其實不同卻共用網址，後面那篇會消失。網頁上兩篇同網址本來就是重複，影響很小。
- 怎麼改回來：拿掉 `buildDay` 裡的 `seen` 檢查，並在資料來源端處理重複。

## 2026-11-18 · 準備 · 一般 iPhone 測試用 iOS 27.2 的 17 Pro Max

- 遇到什麼問題：這台 Mac 上的 iOS 27.1 模擬器 runtime 只支援 iPhone Duo 這個裝置類型，沒有一般 iPhone 可選。
- 考慮過的做法：(1) 只測 Duo；(2) 另外裝 27.1 以外的 runtime 給一般 iPhone；(3) 一般 iPhone 用已經裝好的 iOS 27.2。
- 選了哪個、為什麼：選 (3)，建立「Jihchih 17 Pro Max」（iOS 27.2）測一般 iPhone，Duo 另用「Jihchih Duo」（iOS 27.1）。不用額外下載，兩種畫面都測得到。
- 選錯的代價：兩台模擬器的系統小版本不同，若有只在其中一版出現的行為，可能要多花時間分辨。
- 怎麼改回來：之後 27.1 runtime 支援一般 iPhone，或裝了其他 runtime，就換掉測試用的模擬器，並更新 `ios/scripts/test.sh`。

## 2026-11-18 · 準備 · Apple 的 Duo 官方文件只讀得到一部分

- 遇到什麼問題：想依 Apple 官方文件設計 Duo 版面，但 iPhone Duo 的 HIG 頁面、`developer.apple.com/documentation/swiftui`、`technologyoverviews/preparing-your-app-for-iphone-duo` 這次只讀得到標題；`uikit/supporting-iphone-duo` 回傳 404。
- 考慮過的做法：(1) 等文件可讀再開始；(2) 憑印象寫；(3) 只採用讀得到的來源，其餘標示為未確認。
- 選了哪個、為什麼：選 (3)。讀得到的來源有 Tech Talk 111461 的逐字稿、論壇討論串 847644（只讀到一部分）、三篇開發者文章（Olivier Bernal、dev.to 上的 ArshTechPro、Swift with Majid）。Duo 版面只依這些來源做，不確定的部分在模擬器上實測。
- 選錯的代價：官方文件可能有這些來源沒提到的限制，要到實測或審查時才發現，屆時要回頭修版面。
- 怎麼改回來：官方頁面能讀時再對照一次，有出入的地方調整版面並補一筆紀錄。
