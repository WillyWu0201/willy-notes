- 狀態：草稿，等使用者確認
- 日期：2026-11-18
- App 名稱：日知，使用者已選定。原本暫稱「資訊摘要」。Bundle ID：`com.willywu.jihchih`。

## 1. 為什麼要做

使用者每天早上想吸收 AI 開發的新知，也順便看 AI 產業、iOS / Apple、金融與虛擬資產的消息。網站 `willy-notes.pages.dev/digest/` 已經每天 09:00 自動更新，但使用者想要原生 App 的閱讀體驗，**以使用者體驗為主**。

使用者已經決定：

- 做原生 App，不做內嵌網頁的套殼。
- 使用者全程留在 App 內：我們自己的按鈕、連結、Widget、通知和 YouTube 播放器，都不會讓讀者跳到 Safari、YouTube、X 等其他 App。
  - 在 App 內的 Safari 畫面裡，如果讀者自己按系統的「用 Safari 開啟」，或點網頁上的「在 App 中打開」，就是讀者自己選擇離開，不必攔。
- 公開上架 App Store。讀者包括使用者本人、同事和其他中文讀者，大多是開發者。

## 2. 目標、不做、失敗條件

**目標**

- 打開 App 就看到最新一天的摘要，跟網站一樣分四類，深度分析卡用原生排版。
- 原文、延伸閱讀、YouTube 影片都在 App 內打開。
- 有網頁做不到的原生功能：離線閱讀、收藏、已讀狀態、每日提醒、主畫面 Widget。
- 通過 App Store 審查並上架。

**第一版不做**

- 帳號登入，以及 iCloud 跨裝置同步。
- 伺服器推播（例如「今天的摘要好了」）。
- iPad 專屬版面、Mac 版、Android 版。
- 搜尋。
- 在 App 內顯示原文全文。
- 數據分析、追蹤、廣告。
- 改動網站現有的頁面。

**失敗條件**（就算功能都做出來，只要發生下面任一項就算失敗）

- 點我們自己畫面上的任何東西（包括 Widget、通知、YouTube 播放器裡的連結），會跳到其他 App。
- App 變成轉載別人文章全文的工具。
- 審查以 4.2（功能太少、只是把網站包起來）或 5.2（智慧財產）退件。
- 資料過期或當天沒更新時沒有標示，讓讀者以為看到的是今天的內容。
- 網站的 JSON 格式改了，已經裝在使用者手機上的舊版 App 整頁空白。

## 3. 做法（已決定）

### 3.1 資料：網站多輸出一份靜態 JSON

App 讀網站在部署時一起產生的靜態 JSON，不另外架伺服器。

其他考慮過的做法：

- 解析網站的 HTML：網站版面一改，App 就壞掉。
- 另外架後端：多一份要維護、要付錢的東西，閱讀體驗也不會更好。

### 3.2 原文與延伸閱讀：App 內的 Safari 畫面（SFSafariViewController）

| 做法 | 不選的原因 |
|---|---|
| 跳到 Safari App | 違反「留在 App 內」 |
| 自己用 WKWebView 或 SwiftUI `WebView` 做瀏覽器 | 沒有閱讀器模式，也不會套用使用者裝的廣告阻擋器；工具列、載入進度都要自己做；Apple 建議第三方網頁用 Safari View Controller 開 |
| 在 App 內用原生排版顯示全文 | 等於轉載別人全文，有著作權問題；抓取也常常失敗 |

已知代價：

- 這個畫面的登入狀態跟 Safari 分開。像 X 這種要登入才能看的網站，讀者要在 App 內登入一次。
- 工具列上一定有系統的「用 Safari 開啟」按鈕，拿不掉。網頁本身也可能有「在 App 中打開」的橫幅或連結。使用者決定這兩種算讀者自己選擇離開，不必攔，所以不需要自己做瀏覽器。

### 3.3 YouTube 影片：官方嵌入播放器

用 iOS 26 的 SwiftUI `WebView` 載入 YouTube 官方的 IFrame 播放器，影片直接在詳情頁上方播放。不能自己抓影片串流，這違反 YouTube 條款。

以下兩種情況，改用 App 內 Safari 畫面打開影片頁：

- 影片作者禁止嵌入。
- 播放器載入失敗。

注意：YouTube 對 App 內的嵌入有 Referer / origin 的要求，沒設定好會顯示播放器錯誤。實作時要照 YouTube 當下的官方文件設定，並在實機上確認可以播。

播放器是我們自己的 WebView，所以播放器裡的連結（YouTube 標誌、影片標題等）由我們攔下來，一律改用 App 內 Safari 畫面打開，不讓它開 YouTube App 或 Safari。

其他考慮過的做法：

- 全部用 App 內 Safari 畫面開影片：做得到，但要看完 YouTube 網頁上的橫幅和登入提示，體驗比較差。
- 開 YouTube App：違反「留在 App 內」。

## 4. 網站要加的東西（willy-notes repo）

### 4.1 公開 JSON

`scripts/build-digest.mjs` 的 `buildAll()` 產生 HTML 時，從同一份 `content/digests/{date}.json` 一起輸出 JSON。

- 輸出放在 `public/digest/` 底下，所以每天的 `digest:publish` 會自動 commit 並部署，排程不用改。

**`/digest/api/v1/index.json`**

```json
{
  "schemaVersion": 1,
  "generatedAt": "2026-11-18T09:03:00+08:00",
  "minimumAppVersion": "1.0",
  "categories": [
    { "id": "dev", "label": "AI 開發方式" },
    { "id": "industry", "label": "AI 產業動態" },
    { "id": "apple", "label": "iOS / Apple" },
    { "id": "finance", "label": "金融與虛擬資產" }
  ],
  "days": [
    { "date": "2026-11-18", "total": 15, "counts": { "dev": 2, "industry": 12, "apple": 0, "finance": 1 } }
  ]
}
```

**`/digest/api/v1/{date}.json`**

```json
{
  "schemaVersion": 1,
  "date": "2026-11-18",
  "items": [
    {
      "id": "3f9c0a1b2c3d4e5f",
      "category": "dev",
      "title": "Running the full server-side Datasette Python app in the browser…",
      "url": "https://simonwillison.net/2026/Nov/17/datasette-lite/",
      "source": "Simon Willison",
      "publishedOn": "2026-11-17",
      "summary": "一兩句摘要",
      "deep": true,
      "points": ["…"],
      "questions": ["…"],
      "further": [{ "title": "Datasette Lite", "url": "https://lite.datasette.io/", "note": "…" }],
      "video": null
    }
  ]
}
```

規則：

- 跟網頁一樣，排除 `drop` 的文章和非 http(s) 的網址。
- `id`：網址的 SHA-256 前 16 碼。同一篇文章在不同天的 id 都一樣，收藏和已讀靠它辨認。
- `days` 由新到舊排列，列出所有日期。
- `publishedOn`：原文日期，可能是 `null`。
- `summary` 可能是 `null`，代表那篇沒有分析或分析沒通過驗證，App 只顯示標題。
- `deep` 為 `false` 時，不輸出 `points`、`questions`、`further`。
- `further[].url` 可能沒有，代表文中有提到但沒附連結。
- `video`：由網站判斷，App 不自己解析網址。
  - YouTube 的 `watch?v=`、`youtu.be/`、`shorts/` 三種網址都輸出 `{ "provider": "youtube", "id": "9RKrSF9d2SE" }`。
  - 其他網址輸出 `null`。
- 相容性（重要：上架後，舊版 App 會在讀者手機上留很久）：
  - **只加欄位**：`schemaVersion` 不變。App 會忽略不認得的欄位。
  - **刪除或改變欄位意思**：開新路徑 `/digest/api/v2/`，`v1` 繼續產生一段時間。
  - **出現不認得的分類**：App 用 `categories` 裡的名稱顯示。`categories` 也沒有的分類就略過。
  - **通知舊版 App 更新**：App 的版本低於 `index.json` 的 `minimumAppVersion` 時，顯示「有新版 App，請更新」。要停掉 `v1` 時：
    1. 先把 `v1` 的 `minimumAppVersion` 改成會讀 `v2` 的那個 App 版本。
    2. 等一段時間，讓讀者有機會更新。
    3. 再停止產生 `v1`。
    這個欄位第一版就要有，因為已經裝在手機上的 App，只看得懂 1.0 內建的訊號。
- 測試：用 `node --test` 驗證上面每一條規則，並用真實的 2026-11-18 資料產生一份範例檔，App 的測試會用到。

### 4.2 隱私權政策與支援頁

上架必須要有這兩頁，放在網站上：

- `/app/privacy`
  - App 不收集任何個人資料，沒有帳號，不追蹤。
  - App 只會連到 willy-notes.pages.dev 取得摘要。原文和影片由各自的網站提供。
  - 每日提醒是手機本機的通知，不經過任何伺服器。
  - 影片用 YouTube 的嵌入播放器播放，YouTube / Google 可能依它們的隱私權政策收集資料，附上連結。
- `/app/support`
  - 聯絡 email：`willy.xcoder@gmail.com`。
  - 常見問題：X 要登入、影片不能播、內容沒更新。

## 5. App

### 5.1 畫面

底部分頁：**今天**、**過去**、**收藏**、**設定**。

**今天**

```
┌────────────────────────────────────┐
│ 11月18日 星期三                     │
│ （不是今天時：今天的摘要還沒出來，  │
│   這是 11月17日的內容）             │
│ [AI 開發方式 2][AI 產業動態 12][iOS / Apple 0][金融與虛擬資產 1] │
│ ── 深度分析 ──                      │
│ ● Running the full server-side…     │  ● 未讀
│   Simon Willison · 11/17            │
│   一句話摘要，最多三行……            │
│ ── 其他 ──                          │
│ ● 2026 in LLMs ▶                    │  ▶ 影片
│   AI Engineer · 影片                │
│   摘要一行……                        │
└────────────────────────────────────┘
```

- 分類切換：順序跟網站一樣，點了切換，每個分類標篇數。不用左右滑整頁來切換，左右滑留給卡片的手勢。
- 預設分類的規則跟網站的 `defaultTab` 一樣：從「AI 開發方式」開始，選第一個有文章的分類。
- 沒有文章的分類顯示「今天沒有」。
- 「今天」一律用台北時間（Asia/Taipei）判斷，因為摘要是台北時間早上產生的。
- 每篇文章是一張卡片，右上角有書籤按鈕，點了收藏或取消收藏。「AI 開發方式」先列深度分析，再列其他文章。
- 只有標題的文章：顯示標題和來源，不留空白的摘要行。
- 下拉可以重新整理。打開 App 時會更新；從背景回到 App、距上次更新超過 15 分鐘時，也會更新。
- 點文章時：
  - **深度分析**：進詳情頁。
  - **影片**：進詳情頁，播放器在上方。
  - **其他文章**：直接用 App 內 Safari 畫面開原文，因為摘要在列表上已經看得到。
- 手勢（今天、過去的某一天、收藏、iPhone Duo 展開時的左欄都適用）：
  - 往右滑卡片：標為已讀；已讀的文章則是標為未讀。
  - 往左滑卡片：收藏和分享（系統分享面板，不離開 App）。已收藏的顯示「取消收藏」。在「收藏」分頁，往左滑是移除收藏。
  - 滑到底直接執行第一個動作（已讀，或收藏）；滑一半則停住，顯示按鈕。
  - 長按卡片：選單，有收藏、分享、標為已讀或未讀。
  - 手勢不是唯一的做法：卡片上有書籤按鈕，VoiceOver 的動作選單也要有同樣的項目。
  - 從「過去」點進某一天的畫面，往右滑可能跟系統的返回手勢相衝，要在模擬器上確認。有衝突的話，那個畫面的已讀改放到往左滑的按鈕裡。
- 打開詳情頁或原文時，自動標為已讀。

**詳情頁**

```
┌────────────────────────────────────┐
│ [ YouTube 播放器（只有影片才有）]   │
│ 原文標題（保留原文語言）             │
│ Simon Willison · 2026-11-17          │
│ 一句話摘要（大字）                   │
│ 重點                                 │
│  • …（3–5 條）                       │
│ 反思問題                             │
│  • …（2–3 條）                       │
│ 延伸閱讀                             │
│  • Datasette Lite — 說明             │  有連結：點了用 App 內 Safari 畫面開
│  • 某工具（文中提到，未附連結）— 說明 │
│ [          閱讀原文          ]       │  固定在底部
└────────────────────────────────────┘
工具列：收藏、分享
```

**過去**：列出所有日期和各分類篇數，點進去跟「今天」是同一個畫面，只是換成那一天的資料。

**收藏**

- 依收藏時間排列，可以滑動刪除。
- 收藏時把整篇資料（標題、網址、來源、日期、摘要、重點、反思問題、延伸閱讀、影片）存一份在手機上。所以收藏的文章離線也能看，網站上那一天就算拿掉了也還在。

**設定**

- 每日提醒：開關加時間，預設關閉，預設時間 09:30。
  - 打開開關時才詢問通知權限。
  - 通知是本機排程的，內容固定為「看看今天的資訊摘要」。App 不知道當天有沒有更新，所以不寫「已更新」。
  - 通知權限被拒絕時，開關回到關閉，用文字說明要到 iPhone 的「設定」打開通知。不放會跳到「設定」App 的按鈕。
- 用閱讀器模式開原文：預設開啟。
- 關於：
  - 說明摘要由 AI 整理，可能有錯，以原文為準。
  - 金融相關內容只是新聞摘要，不構成投資建議。
  - 資料來源，以及網站連結（用 App 內 Safari 畫面開）。
  - 隱私權政策、聯絡方式、版本號。

**主畫面 Widget**

- 小尺寸：日期和四個分類的篇數。
- 中尺寸：今天第一篇深度分析的標題和一句話摘要。沒有深度分析時，改顯示「AI 產業動態」的第一篇。
- 點 Widget 會打開 App，直接到那篇文章或「今天」。
- Widget 自己會連網更新。連不上時讀 App 存下的快取（兩者透過 App Group 共用）。

### 5.2 資料、快取、離線

- 網址：`https://willy-notes.pages.dev/digest/api/v1/`，寫在程式裡。
- 每次抓到的 JSON 都存進 App Group 的資料夾，App 和 Widget 共用。保留最近 30 天，收藏另外存，不受影響。
- 連不上網時，顯示快取的內容，並加上提示：「離線中，顯示 11/18 09:12 更新的內容」。
- 完全沒有快取時，顯示空白狀態和「重試」按鈕。
- App 版本低於 `minimumAppVersion` 時，照樣盡量顯示內容，另外加一條提示：「有新版 App，請更新」。點提示會在 App 內顯示 App Store 的頁面（StoreKit），不跳到 App Store App。
- 已讀狀態：記錄 id 和讀取時間，超過 90 天的自動清掉。
- 收藏和已讀用 SwiftData 儲存。
- App 和 Widget 都附隱私清單檔（`PrivacyInfo.xcprivacy`）：寫明用到的需要說明理由的系統 API，UserDefaults（存設定）和檔案時間（判斷快取新舊），並寫明不追蹤、不收集資料。缺這個檔案送審會被退。

### 5.3 外觀與無障礙

- 使用系統元件和 iOS 26 的預設外觀（Liquid Glass）。主色沿用網站：淺色 `#3B5BDB`、深色 `#8AA0F2`。
- 全面支援 Dynamic Type，最大字級時文字不截斷。
- VoiceOver 會唸出「未讀」「影片」「深度分析」。
- 支援深色模式。
- 介面只有繁體中文。原文標題保留原文，不翻譯。

### 5.4 技術

- 最低支援 iOS 26，只做 iPhone 版，包含 iPhone Duo（見 §13）。
- 用 Xcode 27.1 和 iOS 27.1 SDK 建置。iPhone Duo 要用這一版建置才會滿版，Duo 模擬器也在這一版。只有 iOS 27.1 才有的 API 要用 `#available` 判斷。
- 版面跟著可用寬度伸縮，不判斷機型，也不判斷方向。
- Swift 6（嚴格並行檢查），使用 SwiftUI、SwiftData、WidgetKit、SafariServices、WebKit（SwiftUI `WebView`）、UserNotifications、StoreKit，不用第三方套件。
- 影片的詳情頁沒有重點和反思問題，底部按鈕是「開啟影片頁面」，用 App 內 Safari 畫面開 YouTube 網頁。
- 專案放在 willy-notes repo 的 `ios/` 資料夾。理由是 JSON 格式和 App 的解碼要一起改，也能共用測試資料。
- 開發一律在 worktree 進行，主資料夾維持在 `main`，避免擋到每天 09:00 的 `digest:publish`。
  - `digest:publish` 要求主資料夾在 `main` 上，而且 `public/`、`functions/`、`lib/` 沒有未 commit 的變更。
  - `ios/` 不在它檢查的路徑內，所以 App 的程式碼本身不會擋到部署。
- 測試（Swift Testing）：
  - 解碼網站產生的範例檔。
  - 刻意做出來的邊界資料：`summary` 是 `null`、影片、沒附連結的延伸閱讀、不認得的分類、`schemaVersion` 2。
  - 預設分類的規則。
  - 快取：連不上網時退回快取。
  - 已讀紀錄的清理。

## 10. 決定（使用者已在 2026-11-18 全部確認）

1. **一般文章不進詳情頁，直接開原文。** 摘要已經在列表上，多一頁只是多點一下。深度分析和影片才進詳情頁。
2. **第一版就做 Widget 和本機的每日提醒。** 公開上架要避免被 4.2 退件，這兩樣也最貼近「早上打開來看」的習慣。伺服器推播需要多架服務，放到之後。
3. **第一版不做搜尋和 iCloud 同步。** 這兩項是可以晚點加的功能，不影響第一次審查。
4. **只做 iPhone 版，最低 iOS 26。** 只做 iPhone 就不用準備 iPad 截圖和版面。iOS 26 才有 SwiftUI `WebView`，現在也已經是 iOS 27 的時代了。
5. **App 放在 willy-notes repo 的 `ios/`。** JSON 格式和 App 一起改，測試資料也共用。
6. **JSON 用 `/digest/api/v1/` 路徑，並由網站判斷是不是影片。** 上架後舊版 App 會留很久，路徑帶版本號才能安全地改格式。判斷規則放在網站，App 和 Widget 就不會各寫一套。
7. **每日提醒預設關閉，提醒文字不寫「已更新」。** App 不知道當天有沒有更新，硬寫「已更新」可能是錯的。
8. **關於頁註明 AI 整理和「不構成投資建議」。** 對讀者透明，也降低審查的疑慮。
9. **用 `minimumAppVersion` 通知舊版 App 更新，不用 `schemaVersion`。** 已經裝在手機上的 App 只看得懂 1.0 內建的訊號，所以第一版就要有這個欄位。只加欄位時版本號不變，`schemaVersion` 永遠不會觸發提示。
10. **「今天」用台北時間判斷。** 摘要是台北時間早上產生的。
11. **YouTube 播放器裡的連結由我們攔下來，改用 App 內 Safari 畫面打開。**
12. **通知權限被拒絕時只用文字說明，不放「前往設定」按鈕。** 那個按鈕會跳到「設定」App，不符合留在 App 內。代價是讀者要自己去找設定。
13. **介面只有繁體中文。** 內容本身就是中文摘要。
14. **更新提示在 App 內顯示 App Store 頁面。** 直接開 App Store App 會離開我們的 App。
15. **iPhone Duo 展開時，每一種文章都顯示在右邊。** 兩欄版面的右邊需要內容；一般文章直接跳出原文會蓋掉列表。代價是展開和闔上時，點一般文章的行為不同。
16. **幾欄看寬度決定（大約 700 pt 以上才兩欄）。** 展開後轉成直的只有 669 pt 寬，放兩欄的話每一欄比最小的 iPhone 還窄；並排時也一樣。
17. **分頁和工具列用系統預設的位置。** 用標準元件，系統會依每種姿態自動排。
18. **半開和立起來時不做特別的版面。** 這是閱讀用的 App，依摺疊角度變化版面的幫助不大。
19. **Widget 在 Duo 上沿用小、中兩種尺寸。**
20. **支援所有方向。** Duo 的內螢幕不一定會遵守 App 鎖定的方向，Apple 的說法前後不一。
21. **手勢的方向：往右滑已讀，往左滑收藏和分享。** 跟 iPhone 內建的「郵件」一樣，讀者不用重新學。
22. **分類不用左右滑整頁來切換。** 左右滑已經留給卡片的手勢，兩種手勢放在同一個方向會互相搶。
23. **內文字級是在系統字級上加減。** 「標準」等於系統目前的字級，其他三級是往下一級、往上一級、往上兩級。系統設定的字級照樣有效。
24. **進度圓環只顯示，不能點。** 畫布把它畫成按鈕，但沒有定點了會怎樣。
25. **標題用系統的襯線字，不內建 Noto Serif TC。**（使用者已確認）英文標題是襯線，中文標題會是系統的黑體。
26. **分類標籤照畫布客製。**（使用者決定）選中的填深色，其他白底細框，0 篇的用虛線框，可以橫捲。這是「全部用原生元件」唯一的例外。
27. **分類順序固定，0 篇的不移到最後。**（使用者已確認）每個分類每天都在同一個位置；0 篇的留在原位，用虛線框。
28. **影片卡不載入 YouTube 的縮圖，用深色底加播放鍵。**（使用者已確認）打開列表時不會連到 YouTube，離線時也長得一樣。
29. **不顯示「數量異常」標示。** 收集程式已經擋住舊文洗版；「待修正」給公開讀者看不好；每天的排程會在回報裡提醒使用者。

## 13. iPhone Duo

iPhone Duo 是 2026 年秋天推出的摺疊 iPhone，使用者要求第一版就支援。開闔時 App 不會重新啟動，只是版面大小改變。

### 13.1 各種姿態的版面

版面看可用的寬度決定：大約 700 pt 以上用兩欄，不夠就用單欄。不判斷機型，也不判斷方向。

| 姿態 | App 拿到的大小 | 版面 |
|---|---|---|
| 闔上，直拿 | 466 × 678 pt | 單欄，跟一般 iPhone 相同 |
| 闔上，橫拿 | 678 × 466 pt | 單欄 |
| 展開 | 951 × 669 pt | 兩欄：左邊列表、右邊文章，在摺線分開 |
| 展開後轉成直的 | 669 × 951 pt | 單欄，內文置中，最寬 640 pt |
| 半開，或立起來 | 跟展開相同 | 兩欄 |
| 兩個 App 並排 | 大約一半寬 | 單欄 |

兩個螢幕的大小已經從這台 Mac 上 Xcode 27.1 的 Duo 模擬器設定檔核對過（外螢幕 1398 × 2034 px @3x；內螢幕以 2007 × 2853 px @3x 繪製）。

### 13.2 展開時的規則

- 兩欄在摺線分開，按鈕和文字不跨過摺線。
- 每一種文章都顯示在右邊。深度分析和影片的內容跟詳情頁相同；一般文章顯示標題、完整摘要和「閱讀原文」。
- 剛展開、還沒點文章時，右邊自動顯示目前分類的第一篇。
- 「過去」：左邊先選日期，再選文章，右邊顯示文章。「收藏」：左邊清單，右邊文章。「設定」：單欄，置中。
- 時間、鏡頭、工具列按鈕和分頁的位置由系統決定。App 用標準元件，不自己畫。
- 支援所有方向，一般 iPhone 橫拿也可以用。

### 13.3 開闔時的接續

- App 不重啟，也不回到第一個畫面。分類、捲動位置、正在看的文章都保留。
- 在列表時展開：左邊是同一個列表，右邊自動顯示第一篇。
- 在看文章時展開：左邊列表標出那一篇，右邊是同一篇、同一個位置。
- 闔上時，右邊是讀者自己點開的文章：顯示那一篇，按返回回到列表。
- 闔上時，右邊是自動顯示的那一篇，而且沒碰過：顯示列表。
- 自動顯示的那一篇不算已讀。讀者點了它，或捲動了右邊的內容，才算已讀。
- App 內的 Safari 畫面、選單、分享面板開著時開闔：留在原地，由系統調整大小。
- 影片播放中開闔：目標是不中斷。做不到的話，至少停在同一支影片。

### 13.4 驗收

- 在 Duo 模擬器上，闔上直拿、闔上橫拿、展開、展開後轉成直的都能正常使用，沒有被切掉或疊在一起的內容。
- 展開時是兩欄，摺線上沒有按鈕或文字。
- 開闔時，分類、捲動位置、正在看的文章都保留。
- 跟另一個 App 並排時能正常使用。
- 一般 iPhone 上的畫面，跟加入 Duo 之前一樣。

### 13.5 還沒確認的事

做到那個階段時，要在模擬器或實機上確認：

- App 內的 Safari 畫面在內螢幕的樣子。
- 分頁列在外螢幕是在底部還是右邊。
- YouTube 的嵌入播放器在開闔時會不會中斷。
- App Store 要不要另外交 Duo 的截圖。

## 14. 畫面重新設計與原生元件

2026-11-18 使用者提供了設計畫布（https://claude.ai/artifact/4iEFZUXWayZHM9QN9q9WNg），並要求全部元件都用系統原生的。

### 14.1 原則

- 畫面稿決定的是版面、內容和順序。每一樣東西實際用哪個系統元件，照 14.2 的表。畫面稿跟系統元件長得不一樣的地方，以系統為準。
- 分頁列、導覽列、導覽列上的按鈕、標題、副標題、清單、按鈕、開關、滑桿、選單、進度條、分享面板、空白狀態，都用系統元件，不自己畫。唯一的例外是分類標籤，照畫布客製（§10 第 26 條）。
- 顏色用系統的語意色，藍色（`#3B5BDB`）設成 App 的強調色。字體用系統的文字樣式，圖示用 SF Symbols。
- 可以點的東西，點擊範圍至少 44 pt。文字和底色的對比至少 4.5:1。

### 14.2 對照表

| 畫面上的東西 | 用哪個系統元件 | 跟畫面稿不一樣的地方 |
|---|---|---|
| 分頁列 | `TabView` | iOS 26 的系統分頁列本來就是浮動的膠囊；高度、材質由系統決定 |
| 大標題和日期 | 導覽列的大標題和副標題 | 日期和「幾篇、幾點更新」在標題下面，不在上面 |
| 進度圓環 | 導覽列右邊的項目，用 `Gauge` | 大小跟導覽列上的其他按鈕一致 |
| 返回、Aa、收藏、分享 | 導覽列的系統按鈕 | Aa 點了出現系統選單，從四級裡選 |
| 分類標籤 | 客製，照畫布（§10 第 26 條） | 選中的填深色，其他白底細框，0 篇的用虛線框 |
| 文章卡片 | 系統清單的圓角區塊，每篇一塊 | 沒有陰影，圓角由系統決定 |
| 標題的襯線字 | 系統的襯線字型 | 英文是襯線，中文是系統的黑體 |
| 內文 | 系統的內文樣式 | 17 pt、行高 1.85 是標準字級下的樣子 |
| 閱讀進度條 | `ProgressView` | 沒有 |
| 一句話摘要、想一想的色塊 | 系統的群組區塊，套淡藍和淡黃的底色 | 圓角由系統決定 |
| 閱讀原文、開啟影片頁面 | 系統按鈕的主要和次要樣式，放在底部工具列 | 沒有 |
| 收藏的篩選 | 系統的分段控制 | 沒有 |
| 過去的比例色條 | Swift Charts 的堆疊長條 | 沒有 |
| 設定 | 系統的表單：滑桿、開關、時間選擇器 | 提醒關閉時，時間選擇器由系統自動變灰 |
| 長按選單、滑動動作、分享 | 系統的選單、清單滑動動作、分享面板 | 沒有 |
| 空白狀態 | `ContentUnavailableView` | 沒有 |

### 14.3 畫布帶來的新功能

- **今天的進度和下一類**
  - 導覽列右邊顯示當天的閱讀進度：已讀幾篇、一共幾篇，四個分類合計。看「過去」的某一天時，顯示那一天的進度。
  - 導覽列的副標題（在大標題下面）顯示日期、當天的篇數和更新時間。
  - 捲到一個分類的底部，顯示「這一類看完了」和下一個有文章的分類，點了切換過去。最後一個有文章的分類不顯示。
- **閱讀頁**
  - 導覽列下面有閱讀進度條，跟著捲動位置走。
  - 「反思問題」在畫面上改叫「想一想」，資料的欄位名稱（`questions`）不變。
  - 重點用 01、02 編號，想一想用 Q1、Q2 編號。
  - 文末有「下一篇」：同一天、同一個分類裡排在後面的那一篇。這一類的最後一篇不顯示。
  - 影片頁的摘要區塊叫「這支影片在講什麼」，底部按鈕用次要樣式。
- **內文字級**
  - 四級：小、標準、大、特大。預設「標準」。
  - 閱讀頁的 Aa 和「設定」都能改，是同一個設定。設定頁有即時預覽。
  - 只影響文章內容，列表、導覽列、分頁列不受影響。
  - 跟系統字級並存的方式見 §10 第 23 條。
- **收藏**
  - 可以篩選：全部、深度、影片、文章，各標出篇數。預設「全部」。
  - 每張卡標出種類、來源、「已存在手機」和收藏的時間。
- **過去**
  - 每天一列：日期、總篇數、四類的比例色條、各類幾篇。上方有四類的顏色圖例。
  - 依週分組：這一週、上一週，更早的用日期範圍當標題。
  - 不顯示「數量異常」之類的標示（第 29 條）。
- **設定**
  - 項目：內文字級、用閱讀器模式開原文、每日提醒、提醒時間。提醒關閉時，提醒時間不能點。

### 14.4 跟畫布不一樣的地方

- 日期改用導覽列的副標題，放在大標題下面。
- 分類順序固定，0 篇的留在原位（§10 第 27 條）。
- 標題用系統的襯線字（§10 第 25 條）。
- 規格書的畫面稿全部照這三點重畫，有淺色和深色。深色的配色是依淺色推出來的，實作時改用系統的語意色。
- S16 在規格書裡是「iPhone Duo 展開 · 深度分析」，S17 是「展開 · 影片」；畫布上的 Duo 畫面對應規格書的 S15（一般文章）。

### 14.5 驗收

- 分頁列、導覽列、標題、按鈕、清單都是系統元件，程式裡沒有自己畫的分頁列或導覽列。
- 內文字級四級都能切換，閱讀頁和設定頁顯示同一個設定。系統字級調到最大時，文字不截斷。
- 進度圓環的數字正確；分類底部的「下一類」和文末的「下一篇」點了會到對的地方；收藏的篩選結果正確。
